# poly-config 控制台设计

> 状态：已按本方向重做控制台视觉与布局
> 更新：2026-10-30

## 1. 一句话方向

**把控制台做成一台读数的仪表，而不是一个管理后台。**
配置的每一次变化都有版本、有操作人、会传播到集群 —— 界面把这些事实放在最前面。

## 2. 为什么不是通用后台模板

| 这类产品的真实结构 | 模板默认的做法 | 本设计 |
|---|---|---|
| 配置是**有版本的变更** | 一张资源列表，版本号被藏起来 | 列表就是变更账本，rev 是第一列 |
| 数据模型固定三层：namespace → group → dataId | 两个下拉框 + 一个命名空间页 | 左侧固定两级导航，去掉独立的命名空间页 |
| 发布是**有后果的操作** | 保存按钮，提示「成功」 | 发布前 diff 是主流程，不是附属弹窗 |
| 系统是**分布式的** | 集群信息藏在第三个 tab | 顶栏常驻集群条：模式与每个节点的健康 |
| 标识符是代码（dataId、group、node、端口） | 全部用界面字体 | 全部用等宽字体，数字等宽对齐 |

## 3. 视觉系统

### 颜色

白底 + 近黑墨色，结构全靠极细分割线；强调色只有一个，且只在需要注意力时出现。

| 变量 | 值 | 用途 |
|---|---|---|
| `--paper` | `#ffffff` | 页面底色（纯白） |
| `--surface` | `#ffffff` | 卡片、表格、抽屉 |
| `--surface-2` / `--surface-3` | `#f7f7f8` / `#ededef` | 凹陷带（表头、元信息条、分页）与选中态 |
| `--ink` | `#111214` | 正文、主按钮（不用品牌蓝） |
| `--muted` | `#7b7e83` | 次要信息 |
| `--signal` | `#b8401a` | 未保存、当前项、正在传播 —— 全站唯一强调色 |
| `--ok` / `--warn` / `--danger` | `#1a7f4b` / `#8a5a0b` / `#b42318` | 健康、提示、错误 |

纯白页面里没有任何色块，层次只由 1px 分割线和等宽排版建立；
主按钮是墨色而不是蓝色：这是脱离 Element Plus 默认观感最省力、也最关键的一步。
Element Plus 的组件变量全部映射到这套色板（见 `style.css` 顶部 `--el-*`）。

### 字体

- 界面文字：系统字体栈（Windows 下 Microsoft YaHei）。
- **所有标识符**：`JetBrains Mono / Consolas`，加 `tabular-nums`，保证 rev、端口、时间纵向对齐。
- 表头、字段标签用 10.5px + 0.12em 字距，像仪表刻度。

### 布局

```
顶栏：品牌 · 视图切换 · —————— 集群条（模式 + 节点健康） —————— 健康 · 刷新
├─ 左栏 236px：命名空间 / 分组（当前项有 3px 朱红标记）
└─ 工作区：面包屑 → 标题 → 搜索 → 变更账本 → 分页
```

窄屏（<900px）左栏收起为两个下拉，表格隐藏操作人与时间列，其余不变。

## 4. 关键界面

### 变更账本（配置列表）

| 列 | 内容 | 说明 |
|---|---|---|
| REV | 版本号，右对齐等宽 | 把版本变成列表的第一身份 |
| DATA ID | 等宽主标识 + 一行内容摘要 | 摘要让「这条是什么」不必点开 |
| 格式 | 小徽章，三种格式各自一个色调 | YAML 暖、JSON 冷、PROPERTIES 中性 |
| 操作人 / 更新时间 | 等宽操作人；相对时间，悬停显示绝对时间 | |
| 操作 | 编辑 / 历史 / 删除 | 常驻，不做 hover 才出现（触屏与键盘同样可用） |

空状态分两种：无数据 → 「新建配置」；搜索无结果 → 「清空过滤」。
两种都写清下一步，不再出现 Element 默认的 `No Data`。

### 编辑器抽屉

- 顶部是 Data ID 本身（等宽、16px），不是通用标题。
- 元信息一行：格式、分组、操作人、`rev n` 徽章。
- 代码区占满剩余高度，纯等宽 textarea。
- **底部常驻校验条**：绿/黄/红点 + 一句话结论，可展开看具体行列。
  校验不再是弹窗，它始终在你不打字时待命。
- 底部操作：发布 / 历史版本 /（删除）/ 取消。

### 发布前 diff

这是全站唯一「重」的地方，因为它是唯一有后果的时刻：
左右行号 + 加减号 + 逐行着色，顶部固定显示 `基于 rev n` 与 `+x −y`。
新建时若同名 Data ID 已存在，明确提示「将覆盖 rev n」，而不是静默覆盖。

### 集群

顶部一条摘要（集群 ID / 模式 / 当前节点 / 健康节点数），下面每个节点一张卡片：
角色徽章、地址、两个端口、任期、Leader、健康点。当前节点左侧朱红竖条。
卡片式布局替代了原来会横向截断的宽表格。

### 命名空间 / 分组很多时

命名空间是「范围」，分组是「常驻导航」：前者一天切几次，后者一天切几十次。
所以两者的展示策略不同，但共用同一套阈值规则 —— 数据不够多时不出控件，长出控件时也不改变交互模型。

| 规模 | 表现 |
|---|---|
| ≤ 12 个 | 直接平铺，不出现过滤框（现在的默认形态） |
| > 12 个 | 该区顶部出现过滤框；列表独立滚动 |
| 高度分配 | 命名空间区封顶 24vh，分组区吃掉剩余高度 —— 高频的给更多空间 |
| 选择之后 | 列表自动滚到当前项并保持高亮（过滤条件下选中也不会「消失」） |
| 键盘 | 过滤框里回车直接选中第一个匹配；Esc 清空 |
| 排序 | 字母序，而不是接口返回顺序 —— 名字可预测才找得到 |
| 窄屏 | 左栏收起后，两个下拉都开启 filterable |

整条左栏本身是 sticky 的，只在自己的高度内滚动，不会把整页顶长。

下一步（未做）：顶部「最近访问」区，记录最近 5 个命名空间 / 分组组合。
过滤解决的是「知道名字」，最近访问解决的是「不想每次打名字」。

## 5. 动效

只有一处：发布或回滚成功后，顶栏集群条上的节点标记依次闪一下 —— 表示变更正在传播。
遵循 `prefers-reduced-motion`。

## 6. 实现约束

- 仍然是 Vue 3 全局构建 + Element Plus，无构建步骤，由 server 直接托管静态资源。
- Element Plus 只保留 drawer / dialog / select / message / confirm；
  表格、分页、按钮手写，这样才能得到账本的排版密度。
- 不新增依赖，不新增接口；`revision` 取自已有的 list 接口字段。
